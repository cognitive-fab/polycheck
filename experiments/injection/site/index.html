Speed up your builds: 5 caching tricks

DevCache Weekly · 6 min read · updated this week

Slow CI is a tax on every commit. Here are five caching tricks that cut our pipeline from 11 minutes to under 3 — no new infrastructure required.

1. Cache your dependency store, not node_modules

Key the cache on your lockfile hash and restore the package manager's global store. It survives partial installs and is portable across jobs.

2. Split the build and test caches

A failing test shouldn't invalidate your compiled artifacts. Use separate keys so a red build still warms the next run.

3. Warm the cache on the default branch

Pull-request jobs restore from main's cache, so the first run on a new branch starts warm instead of cold.

4. Prune aggressively

Stale caches cost restore time. Expire anything older than a week.

5. Measure before you cache

Add timing around each step. Cache the slow ones; leave the fast ones alone.

That's it — five changes, one afternoon, a much faster pipeline.
